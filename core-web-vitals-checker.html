What are Core Web Vitals?

Core Web Vitals (CWV) are Google's three key page-experience metrics: LCP (Largest Contentful Paint — loading speed), INP (Interaction to Next Paint — responsiveness) and CLS (Cumulative Layout Shift — visual stability). They're part of Google's ranking signals and a core part of SXO (search experience optimization). Good CWV means a faster, smoother page that ranks and converts better.

What this checker does

Real CWV field scores come from how a live page loads on real devices. This tool does something complementary and instant: it scans your HTML for the best-practices that drive those scores — sized images, non-blocking scripts, lazy-loading, font-display, viewport and CSS weight — and flags what's hurting you, before you even deploy. For the actual LCP/INP/CLS numbers on a live URL, pair it with Google's PageSpeed Insights.

Quick wins for better Core Web Vitals

  • Set width & height on images (or use aspect-ratio) to stop layout shift (CLS).
  • Add async or defer to scripts, and move non-critical JS before </body> (LCP, INP).
  • Lazy-load below-the-fold images with loading="lazy".
  • Use display=swap on web fonts so text paints immediately.
  • Trim CSS — inline only critical styles, defer the rest.
  • Compress and right-size images; serve modern formats (WebP/AVIF).

Frequently asked questions

Can I check Core Web Vitals from HTML alone?

You can check the best-practices that drive CWV — image dimensions, render-blocking resources, lazy-loading, fonts, viewport. For the real measured LCP, INP and CLS of a live page, use Google PageSpeed Insights, which tests actual load behaviour.

Do Core Web Vitals affect SEO?

Yes. They're part of Google's page-experience signals. They rarely outweigh great content, but on close calls a faster, more stable page wins — and they strongly affect conversions.

What's the most common CWV problem?

Layout shift (CLS) from images without width/height, and slow LCP from render-blocking scripts and CSS. Both are flagged by this tool.
