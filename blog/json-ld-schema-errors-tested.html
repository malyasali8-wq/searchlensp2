12 JSON-LD and Schema Markup Mistakes: Real Tests and Fixes

By Muhammad Ilyas, SEOGlint

Blog · Tests documented and published November 26, 2026 · Method: examples submitted manually to the SEOGlint Schema Markup Validator

We submitted 12 flawed JSON-LD snippets to the SEOGlint validator and recorded exactly what it reported, with screenshots and suggested fixes.

Structured data helps describe entities such as organizations, articles, products, events, and videos. But small mistakes in JSON-LD can make markup unreadable—or leave important properties missing. The challenge is knowing whether a problem is a JSON syntax error, a schema-property issue, or a warning from a particular validator.

We documented 12 distinct test cases using the SEOGlint Schema Markup Validator and retained 13 screenshots. One Organization missing-name test was captured twice and is counted once. This article shows the exact messages observed in SEOGlint, the submitted snippets, and suggested corrected versions. If you are looking for how to fix JSON-LD syntax errors, or how to validate schema markup before publishing a page, the 12 cases below cover common causes and what each message looked like.

Scope of this research: These are observations of SEOGlint's own checker, not a comparison benchmark or proof of Google rich-result eligibility. We have not supplied independent test outcomes from Google's Rich Results Test or Schema.org Validator. The corrected examples below are proposed code fixes and should be tested again before being used on a live website.

Quick answer: how do you fix JSON-LD schema errors?

Start by checking whether the snippet is valid JSON: use double-quoted keys and strings, add commas between properties, and remove trailing commas. Then confirm that @context, @type, and the properties appropriate to the chosen schema type are present. Finally, check the markup against a Schema.org validator and, if you are targeting a Google search feature, Google's Rich Results Test. Valid JSON, meaningful Schema.org markup, and Google rich-result eligibility are three different checks.

The 12 tests: original inputs, observed results, and suggested fixes

The screenshots below are original captures of SEOGlint's interface. Error messages are transcribed from the screenshots. Sample domains, products, events, and dates are illustrative—not verified real-world entities.

Test 01: Trailing comma after the final JSON property

What we submitted: A comma remains after the last property, immediately before the closing brace.

Submitted in the test
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Example Co",
  "url": "https://www.example.com",
}

What SEOGlint displayed:

Error: Invalid JSON: Expected double-quoted property name in JSON at position 125 (line 6 column 1)

Suggested fix: Remove the comma after the final url value. A JSON-LD trailing comma error like this one is a plain JSON problem, because JSON does not permit trailing commas.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Example Co",
  "url": "https://www.example.com"
}

Test 02: Single quotes instead of double quotes

What we submitted: The input uses single-quoted JSON property names and string values.

Submitted in the test
{
  '@context': 'https://schema.org',
  '@type': 'Organization',
  'name': 'Example Co'
}

What SEOGlint displayed:

Error: Invalid JSON: Expected property name or '}' in JSON at position 4 (line 2 column 3)

Suggested fix: Use double quotes for every JSON key and string value. Single quotes are not valid JSON string delimiters.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Example Co"
}

Test 03: Unquoted JSON property name

What we submitted: The name property is written without quotation marks.

Submitted in the test
{
  "@context": "https://schema.org",
  "@type": "Organization",
  name: "Example Co"
}

What SEOGlint displayed:

Error: Invalid JSON: Expected double-quoted property name in JSON at position 67 (line 4 column 3)

Suggested fix: Wrap the name property key in double quotes.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Example Co"
}

Test 04: Missing comma between JSON properties

What we submitted: There is no comma between the @type value and the next name property.

Submitted in the test
{
  "@context": "https://schema.org",
  "@type": "Organization"
  "name": "Example Co"
}

What SEOGlint displayed:

Error: Invalid JSON: Expected double-quoted property name in JSON at position 67 (line 4 column 3)

Suggested fix: Insert a comma after "Organization". Notice that tests 3 and 4 produced the same parser message, despite different mistakes; inspect the source at the reported location rather than relying only on the wording.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Example Co"
}

Test 05: Missing @context in an Organization object

What we submitted: The object declares @type: Organization but omits the Schema.org context.

Submitted in the test
{
  "@type": "Organization",
  "name": "Example Co",
  "url": "https://www.example.com"
}

What SEOGlint displayed:

Error: Missing "@context" (use https://schema.org)

Warning: @type Organization: consider adding "logo"

Suggested fix: Add "@context": "https://schema.org". A JSON-LD missing @context error means the parser cannot tell which vocabulary the properties belong to. The separate logo message is a suggestion from SEOGlint, not proof that every Organization object must contain a logo.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Example Co",
  "url": "https://www.example.com"
}

Test 06: Organization object missing name

What we submitted: The input has @context, @type, url, and logo, but no organization name.

Submitted in the test
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "url": "https://www.example.com",
  "logo": "https://www.example.com/logo.png"
}

What SEOGlint displayed:

Error: @type Organization is missing "name"

Suggested fix: Add a truthful name matching the organization. A second screenshot showed this same test result; it is not counted as a new case.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Example Co",
  "url": "https://www.example.com",
  "logo": "https://www.example.com/logo.png"
}

Test 07: FAQPage object missing mainEntity

What we submitted: A FAQPage object is present with no question-and-answer entities.

Submitted in the test
{
  "@context": "https://schema.org",
  "@type": "FAQPage"
}

What SEOGlint displayed:

Error: @type FAQPage is missing "mainEntity"

Suggested fix: Add actual visible questions and answers under mainEntity when FAQPage markup is appropriate. Do not assume FAQPage markup will create a Google FAQ rich result; feature availability and eligibility are separate matters.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "What is JSON-LD?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "JSON-LD is a JSON-based format for linked data."
      }
    }
  ]
}

Test 08: BreadcrumbList missing itemListElement

What we submitted: The breadcrumb type is declared without any list items.

Submitted in the test
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList"
}

What SEOGlint displayed:

Error: @type BreadcrumbList is missing "itemListElement"

Suggested fix: Add the real breadcrumb path as ordered ListItem entries with positions and URLs. The markup should match the site navigation.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    {
      "@type": "ListItem",
      "position": 1,
      "name": "Home",
      "item": "https://www.example.com/"
    },
    {
      "@type": "ListItem",
      "position": 2,
      "name": "Guides",
      "item": "https://www.example.com/guides"
    }
  ]
}

Test 09: Event missing startDate and location

What we submitted: The Event contains a name but lacks a start date and location.

Submitted in the test
{
  "@context": "https://schema.org",
  "@type": "Event",
  "name": "SEO Workshop"
}

What SEOGlint displayed:

Error: @type Event is missing "startDate"

Error: @type Event is missing "location"

Suggested fix: Add the real event start time and actual physical or virtual location. The values shown here are illustrative placeholders, not details of a real SEOGlint event.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "Event",
  "name": "Example SEO Workshop",
  "startDate": "2026-12-15T10:00:00+05:00",
  "location": {
    "@type": "Place",
    "name": "Example Venue",
    "address": "Example City"
  }
}

Test 10: Product missing name; nested Offer missing priceCurrency

What we submitted: A Product has a description and nested Offer with a price, but lacks a name and currency.

Submitted in the test
{
  "@context": "https://schema.org",
  "@type": "Product",
  "description": "A test product",
  "offers": {
    "@type": "Offer",
    "price": "29.99"
  }
}

What SEOGlint displayed:

Error: @type Product is missing "name"

Warning: @type Product: consider adding "image"

Error: @type Offer is missing "priceCurrency"

Suggested fix: Provide a real product name and the correct ISO currency code for the offer. SEOGlint also suggested an image. Never invent product details or prices in live markup.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Example Product",
  "description": "An illustrative test product",
  "image": "https://www.example.com/product.jpg",
  "offers": {
    "@type": "Offer",
    "price": "29.99",
    "priceCurrency": "USD"
  }
}

Test 11: VideoObject missing thumbnailUrl and uploadDate

What we submitted: The video object includes a name but omits the thumbnail and upload date.

Submitted in the test
{
  "@context": "https://schema.org",
  "@type": "VideoObject",
  "name": "How to run an SEO audit"
}

What SEOGlint displayed:

Error: @type VideoObject is missing "thumbnailUrl"

Error: @type VideoObject is missing "uploadDate"

Suggested fix: Add a real, accessible thumbnail URL and the correct video upload date. Additional Google video requirements may apply; this sample does not establish rich-result eligibility.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "VideoObject",
  "name": "How to Run an SEO Audit",
  "description": "An illustrative SEO audit tutorial.",
  "thumbnailUrl": "https://www.example.com/video-thumb.jpg",
  "uploadDate": "2026-11-01T09:00:00+00:00"
}

Test 12: Misspelled Schema.org type: Artical instead of Article

What we submitted: The JSON syntax is valid, but the type name is misspelled.

Submitted in the test
{
  "@context": "https://schema.org",
  "@type": "Artical",
  "headline": "Example headline"
}

What SEOGlint displayed:

Warning: @type Artical is not in this checker's rule list, so only syntax was checked. Verify it on schema.org

Suggested fix: Correct Artical to Article. This is a particularly important finding: SEOGlint reported zero errors and one warning because it did not apply type-specific checks. Zero errors in a limited checker is not the same as verified Schema.org validity.

Proposed fix
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Example headline"
}

What these tests actually tell us

1. Four examples failed before schema validation could begin

The trailing comma, single quotes, unquoted key, and missing comma all caused JSON parser errors. In particular, tests 3 and 4 displayed the same parser message and position even though the source mistakes were different. A useful troubleshooting guide should show the code near the reported location, not just repeat the error message. The exact wording and position of parser messages also come from the browser's JSON parser, so another browser may phrase them differently.

2. Seven examples reached schema-related checks

The Organization, FAQPage, BreadcrumbList, Event, Product, and VideoObject examples show missing context or properties according to SEOGlint's rules. The number and severity of messages differ by type. A missing property in this checker does not automatically mean the same field is universally mandatory under Schema.org or that Google will reject the page.

3. The typo example exposed an important limit

Artical (rather than Article) produced zero errors and one warning. SEOGlint explicitly said the type was outside its rule list and only syntax was checked. This demonstrates why zero reported errors is not equivalent to complete semantic validation. A separate vocabulary check is useful.

4. Warnings and errors should not be conflated

The tool suggested adding logo for Organization and image for Product. These were warnings, not the same as the observed missing-property errors. Whether a field is necessary depends on the type, purpose, and search feature being targeted.

A practical validation workflow

  1. Check JSON syntax first. Fix parser errors before interpreting schema properties.
  2. Check the declared type. Confirm that @type is spelled correctly and refers to a recognized Schema.org type.
  3. Review the actual page. The markup must describe content and entities that really exist on the page.
  4. Use a general vocabulary validator. Compare the snippet with Schema.org Validator.
  5. Check Google-specific eligibility separately. Use Google Rich Results Test for relevant supported features. Passing a test never guarantees display.
  6. Keep a reproducible record. Save the input, tool output, test date, and screenshot. Retest after updating the markup or the validator.

Whether you publish in the US, UK, India or anywhere else, the same checks apply, because JSON-LD and Schema.org are not region-specific. A free schema markup validator for structured data errors, such as the SEOGlint checker, is a quick first pass before the other tools. Frequently asked questions

Is valid JSON the same as valid schema markup?

No. A JSON document can parse successfully but contain a misspelled type or inappropriate properties. Test 12 is an example: the JSON syntax was accepted, while the type-specific validation was not performed.

Why does SEOGlint show a warning instead of an error?

The tool distinguishes some recommendations and unsupported checks from errors. In our screenshots, missing logo and image appeared as suggestions, while the unknown Artical type produced a warning that only syntax had been checked.

Does valid schema markup guarantee Google rich results?

No. Google evaluates whether the page, content, markup, and search feature meet its requirements, and may choose not to display a rich result. General structured data validation and Google feature eligibility are separate checks.

Can I use these corrected snippets on my website?

They are illustrative starting points. Replace sample names, URLs, dates, prices, and locations with accurate information. Revalidate the final snippet and confirm that it describes visible content on the page.

Did this study compare SEOGlint with Google's or Schema.org's validators?

No. All supplied result screenshots came from SEOGlint. The other validators are recommended follow-up checks, but their results are not represented as completed experiments here.

Research methodology and limitations

  • Evidence date: November 26, 2026, based on the filenames of the supplied screenshots.
  • Test source: 13 screenshots of the SEOGlint browser-based Schema Markup Validator, covering 12 distinct inputs. Two screenshots show the Organization missing-name case.
  • Method: Enter an intentionally flawed JSON-LD snippet, run the validator, and capture the visible error/warning output.
  • What we can substantiate: The snippets visible in the screenshots and the corresponding messages displayed by SEOGlint.
  • What we cannot substantiate from these screenshots: How Google or Schema.org Validator would respond, whether a corrected snippet was subsequently retested, and whether any markup would receive a rich result.
  • Generalization: These 12 hand-picked cases are examples, not a statistical accuracy, recall, or reliability benchmark for SEOGlint.
  • Future work: Retest corrected snippets and run the same inputs through Schema.org Validator and Google's Rich Results Test, recording the tool version/date and each distinct outcome.
